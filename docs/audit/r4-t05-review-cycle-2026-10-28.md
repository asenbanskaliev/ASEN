# R4 — T05 review freshness audit

Date: 2026-10-28. Base: PR #37 HEAD `18e98728e2e39c8b1a4ebf66019574ee7d1b32a6`.

## Finding: live checkout drift was not revalidated after session creation

- Severity: High.
- Reproduction: create a temporary Git repository with two commits; prepare and bind a candidate; open its review session and result receiver; advance HEAD; attempt to bind the previous candidate result.
- Before correction: session/result validation covered the frozen manifest/view but not the source checkout identity after materialization.
- Correction: private checkout claim retains repository path, directory dev/inode, revision, tree and parent. At session/result boundaries, Git runs with system/global config, fsmonitor, replacement refs, external diff and transport disabled; it checks clean tracked/untracked state and index flags. Session holds its manifest and controller-issued checkout in a private WeakMap. Stale validation invalidates the session and burns the result attempt.
- Independent adversarial pass found the first local draft accepted a caller-provided freshness callback at the session binding boundary. That would let a caller with an open session supply a no-op checker. The final candidate removes the callback parameter: session source binding now accepts only a controller-issued checkout, verifies the checkout claim and exact repository/tree, and calls the controller-owned revalidator internally. A regression verifies forged checkout data is rejected.
- Regression: `tests/work-unit-review-candidate.test.ts`, scenario `F invalidates a session and prior result when the live Git checkout changes`.
- Evidence boundary: this is a local real-Git freshness regression. The fabricated PASS object in the test is only a guard probe; it is not a native RDD observation, reviewer identity or approval.
- Residual risk: a same-user process can race filesystem changes between validations and later reads. The review view is not an OS sandbox or atomic snapshot. Process restart loses WeakMap claims and requires fresh preparation.

## R4 writer-authorization binding follow-up — 2026-10-29

Adversarial review found that a controlled worker's one-use grant and its persisted Todo scope did not bind the live workspace bytes before and after execution. A stale authorization could therefore describe a newer candidate, and terminal completion did not independently reject tracked or untracked writes beyond the granted surfaces.

- **Correction:** controlled-plan apply grants now hold a private, non-durable snapshot of the real Git toplevel, exact `HEAD`, filesystem identity and original bounded surfaces. Dispatch refuses a dirty, replaced, non-toplevel or revision-drifted candidate before the runner starts; it rechecks immediately before the runner receives control and verifies every tracked/untracked result path before a successful result may be accepted. Old grants cannot be reused after a new commit. The check rejects repository and authorized-surface symbolic links, including links introduced after capture. Legacy organic admissions retain their existing semantics and are not represented as this protected controlled-worker path.
- **Reproduction and regressions:** temporary real-Git tests cover a clean allowed write, pre-start drift, a newer committed candidate, tracked and untracked out-of-scope writes, a repository directory link and a linked write surface. Dispatcher tests now run the controlled path against the actual checked-out candidate and retain one-use/concurrent-grant coverage. Focused dispatcher/Pi/snapshot tests passed 87/87; the full local suite on product candidate `6960651a6f5a1ee73a3e8fbbd5ebec16d8a8316f` passed 2,281, failed 0 and skipped 19.
- **Windows journal evidence:** the real two-process journal test, orphan/foreign-lock handling and the bounded Windows `EPERM` contention simulation passed in the focused T05 set. This is Linux-host evidence plus a deterministic Windows-error simulation; it is not evidence that the historical Windows runner failure is causally resolved.
- **Residual blockers:** this is authorization binding, not an OS sandbox. A same-user process can still race path operations after a check, and the evidence executor can write outside its worktree. This host rejected the tested Bubblewrap user-namespace setup and has no Docker or Podman. Public workspace-review correction state is still in memory across a hard restart; isolated candidate tests, candidate-bound acceptance, a valid real provider review, external R4 signoff and final exact-SHA CI remain absent.
