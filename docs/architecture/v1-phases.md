# ASEN v1 Phase Map

## Phase 0 — Architecture and provenance
Pi boundary, upstream baselines, security/authority, lifecycle and capability contracts.

## Phase 1 — Core state
Typed candidate/evidence/task model and deterministic engineering state machine.

## Phase 2 — Agents and authority
Delegation contracts, bounded edit surfaces, single-writer enforcement and Pi process adapter.

## Phase 3 — Flow and Skills
Risk/workflow routing and native Pi Skill composition.

## Phase 4 — Test and Evidence
Candidate-bound executed evidence and strict TDD contract.

## Phase 5 — Review and Verify
Structured findings, immutable candidate binding and risk-proportional verification.

## Phase 6 — Memory
Local SQLite/FTS5 project memory, project/session isolation and context API.

## Phase 7 — Lifecycle
Transactional ASEN-owned changes and diagnostic Doctor.

## Phase 8 — Radar and Registry
Frozen upstream baselines, change classification and capability impact model. Radar never auto-adopts.

## Phase 9 — Cross-platform audit
Linux/Windows CI, architecture gate, E2E-oriented contract tests and final candidate audit. macOS remains a stable-release gate.

A phase is complete only when its implementation and required tests are green on the exact candidate.
