## State model (closed set)

Every plan gets exactly one state. There are no other states; the vocabulary is closed
on purpose, because the current problem is that every plan describes its own state in
prose and none of those descriptions can be compared.

| State | Meaning |
| --- | --- |
| `ACTIVE` | Has open work, and someone is driving it on a live branch/PR right now. |
| `BLOCKED` | Has open work, and progress needs an explicit owner decision or missing external proof. |
| `DONE` | Its stated objective is closed with cited evidence. |
| `SUPERSEDED` | Absorbed by a successor plan; the successor row is named. |
| `HISTORICAL` | Preserved record of executed or abandoned work. Never re-executed. |

`PARTIAL`, `IN PROGRESS` and `DO NOT CLAIM FULL` are **caveats, not states**. They
describe what a plan is not allowed to claim; they do not say whether the plan is still
in play, which is the only question this table answers.

## Authority rule

**One `ACTIVE` plan per front.** A front is a delivery surface, not a topic. Where two
active plans collide on one front, the newer one owns it and the older one is `SUPERSEDED`
with an explicit successor. `AGENTS.md` should point at this table, not at a single
352 KB plan.

Fronts used here: `runtime`, `ui`, `parity`, `ci`, `acceptance`.

### F1 — The canonical plan was truncated by 4,315 lines, then its remnant was destroyed (blocker)

Root cause traced to two commits. Both are in history; both are recoverable.

**Event 1 — truncation, `295c0b1e` (2026-10-27 12:09, "docs(t11): adopt Pi-only scope
and record evidence").** The commit message describes a scope decision. The actual
diff is `4,315 deletions / 5 insertions` on this one file: 4,434 lines and 1,147,743
bytes collapsed to 123 lines and ~60 KB. Lost in that single commit:

| What | Before | After |
| --- | --- | --- |
| Lines | 4,434 | 123 |
| Task IDs | 62 | 29 |
| Log entries `L1`–`L480` | 480 | 0 |
| Headings | 498 | ~16 |

The same commit inserted a 24,530-character line in place of `T09-U4e` carrying a
binary blob (not text). That blob is the origin of everything downstream.

**Event 2 — lossy re-encode, `39cfdbbe` (2026-10-30, "Complete scoped T04 T05 and T07
closure").** This commit converted the blob's decodable mojibake into **17,668 U+FFFD**
characters (verified at byte level: `EF BF BD` inside the file, not a read-encoding
artifact). `EF BF BD` is UTF-8 for the replacement character itself, so the bytes it
overwrote are unrecoverable from the current blob. The count is identical from that
commit to HEAD: the damaged region never changed again, everything after it was ASCII
appends.

**Consequences visible today:** the plan cites log entries that no longer exist inside
it (`L175`, `L474`, `L480`, `L105` appear as references; zero `L<n>` log sections
remain). Ten task IDs from the 2026-10-27 version appear in **no other plan in the
repository** — `T09-U4f`, `T09-U5`, `T09-U6`, `T09-U7`, `T09-U8`, `T09-U9`, `T09-U10`,
`T09-U11`, `T13-audit`, `T14-matrix` — while `T10`, `T11`, `T12` do exist elsewhere
(210, 52 and 254 references) and were re-tracked rather than lost.

**Recovery is complete, not partial.** `a3977fe5:odd/tasks/pi-capability-completion.md`
is the intact pre-truncation document (4,434 lines, 1,147,743 bytes, 0 U+FFFD). Repair
means replaying the intended content of `295c0b1e` (`T04`/`T05`/`T07` FULL rewrites and
the renegotiated-scope paragraph, all readable) plus every later append on top of that
base — not reconstructing anything by guesswork.

**Owner decision, 2026-11-14: this plan is not reconstructed.** It is retained as a
damaged remnant; `a3977fe5` stays as the consultable historical source, not as live
scope. Consequences accepted with that decision: the 480 log entries and the 10 orphan
task IDs stay outside the live plan, and every `L###` reference inside this file points
at history the file no longer contains. Do not treat `pi-capability-completion.md` as
the source of truth until `AGENTS.md` is repointed at this index.

## What this index does not do

- It does not edit, merge, renumber or delete any plan.
- It does not decide delivery, approval or review authority.
- It does not repair F1.
- It does not move the handoff history described in F5.

files without advancing their state; state is derived from the evidence column, and
the date only corroborates it.
