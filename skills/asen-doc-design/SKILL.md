## Activation Contract
Use when creating or restructuring technical/review documentation that must communicate decisions efficiently.
## Hard Rules
- Lead with purpose and actionable summary.
- Put critical constraints before background.
- Use progressive disclosure: quick path first, details later.
- Keep claims synchronized with actual implementation/evidence.
## Decision Gates
| Situation | Action |
| --- | --- |
| Reader needs an action | Put exact next step near the decision |
| Detail is optional | Move below the quick path |
| Claim may drift | Link it to executable/source evidence |
## Execution Steps
1. Identify reader and decision/action.
2. Order content by cognitive priority.
3. Use compact tables/examples where they reduce ambiguity.
4. Validate commands, links and technical claims.
## Output Contract
Return document structure, audience/action, validated claims and unresolved documentation risks.
